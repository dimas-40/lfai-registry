# 072 — 전자소송 AI 에이전트 워크플로: 1호 사건 접수부터 보정명령 대응까지 (2026-09-16~18)

> **교재 소재 메모**: "혼자서 전자소송 AI와 함께하기" 테마 교재용 1차 자료. 이 로그는 실제로 벌어진
> 성공/실패/판단기준 전부를 가감없이 담는다 — 사고(파일 삭제)도 교재에서는 "이래서 이 규칙이 필요하다"는
> 근거 사례로 그대로 쓸 것.

## 배경

박씨(원고 본인)가 2026-09-01 교통사고(접촉사고, 인천 남동구 만수동) 관련 손해배상 소송을
전자소송(ecfs.scourt.go.kr)으로 직접 제기. 변호사 없이 Claude Code가 GUI 자동화로
소장 작성부터 접수, 이후 진행상황 추적, 보정명령 대응까지 전 과정을 수행.

## 1부 — 소장 작성 및 접수 (2026-09-16)

### 핵심 도구
- `ecfs_pyauto.py` (pyautogui 기반, Windows Python) — WSL에서 `win32 API 직접호출`(mouse_event/SendKeys)
  시도했으나 Chrome에 입력이 전달 안 되는 버그 확정, pyautogui로 우회해서 해결.
- 한글 텍스트는 `pyautogui.typewrite()`로 절대 안 됨 — 반드시 `win32clipboard`로 클립보드 세팅 후 Ctrl+V.
- 스크린샷은 PowerShell `System.Windows.Forms.Screen` + `Graphics.CopyFromScreen`으로 캡처 → WSL로 복사 → Read.

### 진행 과정
1. 초안 작성 → 외부(별도 세션) 검토로 청구취지/청구원인 오류 발견·수정(차량번호 오기 등)
2. 증거자료(사진 17장, CCTV, 블랙박스, 수리비견적서)를 이메일/카카오톡에서 회수, 법원 인식용
   파일명(`갑제O호증_내용_촬영일시`)으로 재정리
3. 당사자 등록(원고/피고) → 청구취지 → 청구원인 → 입증서류 첨부 → 인지대·송달료 결제
4. **접수 완료 확정: 사건번호 [사건번호]**([관할 법원])

### 확정된 자율실행 경계선 (1부 기준)
- 공동인증서 비밀번호 입력, 인지대/송달료 실제 결제 확정 — 이 2가지만 박씨 본인.
- 나머지(폼입력/로그인/서류작성/진행조회)는 전부 Claude 자동 처리.

## 2부 — Docker 이미지 & MCP 병렬 작업 (2026-09-17, 참고용 별건)

같은 시기 RVC 음성모델 학습 콜드스타트 제거 작업과 병렬 진행. 상세는
[[071-rvc-cold-start-docker-image-2026-09-17]] 참조 — 전자소송과 직접 관련 없으나
"박씨가 한 세션에서 완전히 다른 두 작업을 동시에 굴린다"는 운영 패턴 예시로 교재에 넣을 만함.

## 3부 — 보정명령 발견 및 대응, 그리고 사고 (2026-09-18)

### 진행상황 추적
- "나의사건검색"(비로그인, 참고용)에서 사건번호+당사자명(2글자 이상)+캡차로 조회 가능.
  **법원 선택 드롭다운이 매우 길어서(전국 법원 목록) 키보드 화살표 탐색이 비효율적** —
  브라우저 select의 문자매칭 점프(예: "i" 입력 시 "인천"으로 점프)를 시도했으나 한글 IME
  문제로 실패, 결국 방향키 반복으로 찾음. **교재 포인트**: 다음엔 이 드롭다운 옵션 순서를
  한 번 전수조사해서 좌표/인덱스 표로 남겨두면 재검색 시간 단축 가능.
- 비로그인 화면은 "법적 효력 없는 참고자료"라 문서 원문 열람 불가 — 보정명령 원문을 보려면
  반드시 "나의전자소송" 정식 로그인이 필요함을 실측 확인.

### 보정명령 내용
- 접수 다음날(09.16) 재판부 보정명령, 09.17 참여관용 보정명령 + 원고에게 등본 송달.
- 내용: 21일 이내 "피고 [상대방 보험사] 주식회사의 법인 등기사항증명서" 제출.
  통상적인 당사자 특정 절차 — 청구 내용에 문제가 있어서가 아님.

### 사고: 클립보드 오조작으로 파일 219개 순간 삭제
- **원인**: PDF를 "다른 이름으로 저장" 다이얼로그에 저장하려고 `paste_korean_text()`로
  파일명 입력창 좌표(700, 700)를 **스크린샷으로 확인 없이 추측 클릭**.
- **결과**: 실제로는 그 좌표에 입력창이 없어 포커스가 파일탐색기(Downloads 폴더) 배경에
  가있는 상태 → `Ctrl+A`(전체선택) → `Ctrl+V`가 삭제성 동작으로 오작동 →
  Downloads 폴더 219개 항목이 순간적으로 휴지통 이동.
- **복구**: 즉시 발견(다음 스크린샷에서 "1,271개 항목을 휴지통으로 이동 중, 18% 완료" 진행바
  포착) → PowerShell `Shell.Application` COM 객체로 휴지통 전체 항목(`InvokeVerb('restore')`)
  일괄 복구 → 소장/접수증/갑제호증 전부 무결성 확인. **실질 피해 없음.**
- **교재 포인트**: AI 에이전트가 GUI 자동화 중 "이 정도면 되겠지"로 좌표를 추측하면 안 된다는
  걸 실제 사고로 증명한 사례. 매 클릭 전 스크린샷 확인 원칙이 왜 필요한지 설명하는 데 최적.

### 사고 이후 확정된 규칙 — "동석 필수 vs 무인 가능"의 재구분
박씨가 사고 직후 "PC 앞에서 지켜봐야겠다"고 판단 → Claude가 "박씨 역할 헌법(실행은 전부 Claude)의
명시적 예외"로 메모리에 저장. 이후 박씨가 스스로 더 정교하게 재구분:

| 구분 기준 | 예시 | 처리 |
|---|---|---|
| **내 문서를 제출/저장** (위험) | 전자소송 "제출" 버튼, 법원 서류 파일저장 | 박씨 PC 앞 동석 필수 |
| **남의 공개정보를 가져오는 것** (안전) | 인터넷등기소 법인등기부등본 열람/발급(결제 포함) | 무인 진행 가능 |
| **단순 조회** (안전) | 나의사건검색, 진행상황 확인 | 무인 진행 가능 |

이 구분 논리(제출 vs 열람, 내 것 vs 남의 것)가 이 사고에서 나온 가장 중요한 산출물.
단순히 "위험하니까 다 동석"이 아니라 **행위의 성격으로 리스크를 나눈 것** — 교재의 핵심 챕터감.

### 시스템 간 인증 비연동 확인
전자소송(ecfs.scourt.go.kr)에 로그인해도 인터넷등기소(iros.go.kr)는 자동 로그인 안 됨 —
공동인증서라는 같은 인증수단을 쓰지만 **사이트별로 독립된 세션**이라 매 사이트 최초
브라우저 보안모듈 접근 허용(Allow/Block 팝업)부터 다시 거쳐야 함. 회원가입은 불필요,
인증서 로그인 절차만 사이트마다 반복.
